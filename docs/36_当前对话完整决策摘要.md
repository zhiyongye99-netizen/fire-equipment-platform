# 当前对话完整决策摘要

## 项目总定位

消防车辆装备采购前决策辅助平台。第一阶段重点不是交易，而是装备库、参数比选、中标参考、供应商认领、资料申请和线索闭环。

## 目标用户

- 消防指战员；
- 战训/采购相关人员；
- 企业专职队、民间救援队等专业用户；
- 消防车辆装备供应商；
- 平台运营人员。

## 四大微信小程序 Tab

1. 首页：行业资讯、中标案例、新装备、供应商动态；
2. 消防圈：专业社区、装备讨论、实战案例、采购避坑；
3. 选装：核心，车辆/灭火/水域/排涝/无人装备等分类、参数筛选、产品对比；
4. 我的：收藏、对比、询价、认证、供应商工作台入口。

## 供应商端决策

供应商需要小程序轻工作台，但大量产品录入、批量导入、证书资料管理应放到 PC 后台。

小程序供应商工作台只做：今日待办、最新线索、审核状态、消息通知、进入 PC 后台。

## 关键 UI 决策

- 微信右上角系统胶囊区域必须避让；
- 页面低密度；
- 字体适合手机；
- 产品详情首屏大图 + 核心参数；
- 参数多的内容分段展开；
- 复杂表单不上小程序。

## 商业判断

商业价值成立，但不是电商。短期卖线索和会员，中期卖数据和工具，长期卖采购前决策能力。

## 冷启动策略

平台用公开资料预建基础产品库，再让供应商认领和补充资料。不要指望供应商一开始上传全量资料。

## 开发策略

不要一次性开发完整系统。按顺序：项目骨架 → 数据库 → API → 供应商后台 → 平台后台 → 小程序选装 → 首页 → 消防圈 → 我的 → 供应商轻工作台。

## 初学者风险

你是强业务、弱代码。必须用文档、提示词、Git、微信开发者工具和验收清单控制 AI，不要让 AI 自由发挥。
