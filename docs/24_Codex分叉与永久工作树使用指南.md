# Codex 分叉与永久工作树使用指南

## 一句话区分

| 功能 | 通俗理解 | 适合场景 |
|---|---|---|
| 分叉（从对话中派生） | 另开一条思路讨论 | 方案比较、Bug 分析、技术路线判断 |
| 永久工作树 | 另开一个固定施工区 | 长期模块开发，如数据库、供应商后台、小程序核心 |

Codex 文档中有 Worktrees、AGENTS.md、Skills、Plugins 等配置入口；AGENTS.md 用于给 Codex 提供项目规则，Worktrees 用于组织多个独立开发工作区。

## 分叉怎么用

适合不确定问题：

- 选装页采用汽车之家风格还是采购工具风格？
- 是否第一版做 Excel 批量导入？
- 微信开发者工具为什么真机请求失败？
- 供应商资料哪些公开、哪些仅平台审核可见？

分叉提示词：

```txt
从当前对话分叉：请分析【问题】，不要写代码，只输出方案、风险和建议。
```

## 永久工作树怎么用

适合长期模块：

```txt
project-scaffold
database-schema
supplier-admin
platform-admin
miniapp-core
```

工作树规则：

- 每个工作树只做一个模块；
- 数据库只允许 `database-schema` 工作树改；
- 小程序工作树不要顺手改后端权限；
- 后台工作树不要顺手改小程序 UI；
- 完成后合并回 develop。

## 初学者建议

最多同时保留 2–3 个活跃工作树。不要一开始开很多，否则你会分不清哪个是最新、哪个能运行、哪个已合并。

## 标准流程

```txt
不确定 → 先分叉讨论
确定要做 → 进入工作树开发
开发完成 → 微信开发者工具验收
验收通过 → Git 提交
阶段完成 → 合并回 develop
```
